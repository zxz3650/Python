# 03-9 이벤트 검토 프로그램 학습자용 골격

이 디렉터리는 03-1~03-8에서 배운 문법을 하나의 작은 프로그램으로 연결하는
학습자용 시작점이다. 완성 구현은 포함하지 않는다. 각 파일의 `TODO`를 순서대로
구현하고 `verify.py`가 관찰하는 공개 동작을 만족시키는 것이 목표다.

검증기는 소스 코드의 내부 변수명이나 구현 방식을 검사하지 않는다. 함수의 반환값,
객체의 공개 상태, 발생한 예외, 사용자에게 전달되는 출력만 확인한다. 따라서 같은
요구사항을 서로 다른 코드 구조로 해결해도 된다.

## 준비와 실행

저장소 원본을 직접 수정하지 않으려면 이 디렉터리를 개인 작업 공간으로 복사한다.

```bash
cp -R examples/03-9-event-review-starter event-review-project
cd event-review-project
```

별도의 외부 패키지는 필요하지 않는다. 현재 실패 단계부터 확인한다.

아래의 `python`은 Python 3 실행 명령이다. Linux나 macOS에서 명령을 찾을 수
없다면 `python`을 `python3`로 바꿔 실행한다.

```bash
python verify.py
```

검증기는 첫 번째 실패에서 멈추고 다음에 구현할 파일과 책임을 알려 준다. 해당
단계를 통과한 뒤 다시 실행한다.

모든 검증을 통과한 뒤 터미널 프로그램을 실행한다.

```bash
python -m event_review
```

예시 명령은 다음과 같다.

```text
add ALLOW 192.0.2.10 443
add DENY 198.51.100.4 22
list
find allow
summary
remove 2
quit
```

## 구현 순서

1. `event_review/models.py`의 `parse_port()`를 구현한다.
2. 같은 파일의 `SecurityEvent` 정규화·검증과 `endpoint()`를 구현한다.
3. `event_review/store.py`에서 등록·조회·검색·삭제·집계를 구현한다.
4. `event_review/commands.py`에서 명령 문자열을 `Command`로 변환한다.
5. `event_review/app.py`에서 출력 형식과 명령 실행을 연결한다.
6. 오류 한 건 뒤에도 계속 처리하는 `process_input()`과 `run_session()`을 구현한다.
7. 내장 `input()`과 `print()`를 연결하는 `main()`을 구현한다.
8. `__init__.py`의 공개 API와 `__main__.py`의 실행 진입점을 완성한다.

`SecurityEvent`와 `Command`는 일반 데이터클래스로 완성한다. 변경 불가능 객체
설계는 이 기본 실습의 필수 조건이 아니다.

`verify.py`에는 자동 검증을 위한 프로세스 실행과 모의 입출력 도구가 들어 있다.
이는 채점 도구의 내부 구현이며 이번 기본과정의 학습 범위가 아니다. 학습자는
검증기 코드를 이해하거나 수정하지 않고 실행 결과만 활용하면 된다.

## 공개 동작 계약

- action은 공백을 제거하고 대문자로 정규화하며 `ALLOW`, `DENY`만 허용한다.
- IP는 앞뒤 공백을 제거한 비어 있지 않은 문자열이어야 한다.
- port는 정수 또는 정수 문자열을 받아 1~65535의 정수로 저장한다. `True`는
  허용하지 않는다.
- 같은 action·IP·port 이벤트를 중복 등록하지 않는다.
- 목록과 검색 결과는 튜플로 반환하며 등록 순서를 유지한다.
- `list` 출력에만 1부터 시작하는 삭제 번호를 표시한다.
- `find` 출력에는 번호를 붙이지 않는다. 검색 결과의 위치를 전체 목록의 삭제
  번호로 오해하지 않게 하기 위해서다.
- `remove NUMBER`는 반드시 전체 `list`에 표시된 번호를 사용한다.
- 값·범위와 관련된 사용자 입력 오류는 `오류: ...`로 남기고 다음 명령을 처리한다.
- 잘못된 타입으로 공개 함수를 호출해 발생한 `TypeError`는 프로그래밍 오류이므로
  세션에서 숨기지 않는다.
- `quit`을 만나면 뒤의 명령은 처리하지 않는다.

오류 문구를 외워서 맞추기보다, 어느 함수가 어떤 잘못된 값을 거부해야 하는지부터
설명한 뒤 구현한다. 검증기는 계약에 명시된 예외의 종류와 외부에서 보이는 결과를
중심으로 판단한다.

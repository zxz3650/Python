# 04-5. CSV 읽기·검증·안전한 출력

CSV는 레코드를 행으로, 필드를 열로 표현하는 텍스트 형식이다. 단순히 쉼표로 나눈 문자열이 아니라 구분자·따옴표·줄바꿈 규칙을 함께 적용하는 형식이므로 `split(",")` 대신 표준 `csv` 모듈을 사용한다.

CSV 자체에는 자료형과 필수 필드를 정의하는 스키마가 없다. 파일을 파싱한 뒤 헤더, 열 개수, 빈 값, 자료형과 값의 범위를 별도로 검증해야 한다.

{% hint style="info" %}
### 🧭 학습 목표

- `csv.reader`와 `csv.DictReader`를 목적에 맞게 선택한다.
- CSV 구분자·따옴표·줄바꿈 규칙을 설명한다.
- 헤더의 누락·중복·알 수 없는 열과 행의 누락·초과 필드를 검증한다.
- 문자열 필드를 필요한 Python 자료형으로 변환하고 범위를 확인한다.
- 오류 레코드의 위치와 원인을 기록한다.
- `csv.writer`와 `csv.DictWriter`로 CSV를 작성한다.
- 스프레드시트가 외부 입력을 수식으로 해석할 수 있는 위험과 출력 정책을 설명한다.
{% endhint %}

## 1. 실습 파일 만들기

다음 코드는 이후 예제에서 사용할 `people.csv`를 만든다. `csv.writer`가 쉼표를 포함한 값을 필요한 방식으로 따옴표 처리한다.

```python
import csv
from pathlib import Path

lab_dir = Path("file-lab/csv").resolve()
lab_dir.mkdir(parents=True, exist_ok=True)
path = lab_dir / "people.csv"
sample_rows = [
    ["name", "age", "city"],
    ["Alice", 20, "Seoul"],
    ["Bob", 22, "Suwon, Gyeonggi"],
]

with path.open("w", encoding="utf-8", newline="") as file:
    writer = csv.writer(file)
    writer.writerows(sample_rows)
```

`newline=""`은 `csv` 모듈이 형식에 맞게 줄바꿈을 직접 처리하도록 한다. CSV 파일을 읽고 쓸 때 모두 지정한다.

## 2. csv.reader로 읽기

`csv.reader`는 각 레코드를 문자열 리스트로 반환한다.

```python
with path.open("r", encoding="utf-8", newline="") as file:
    reader = csv.reader(file)
    for row in reader:
        print(row)
```

위 예제의 `Suwon, Gyeonggi`는 쉼표를 포함하지만 하나의 필드로 읽힌다. CSV 규칙이 처리해야 할 따옴표를 제거한 뒤 실제 값만 반환하기 때문이다.

열의 위치 자체가 의미를 갖는 단순 데이터에는 `reader`를 사용할 수 있다. 헤더 이름으로 필드 의미를 확인하려면 `DictReader`가 더 읽기 쉽다.

## 3. DictReader로 읽기

`csv.DictReader`는 첫 레코드를 기본 헤더로 사용하고 이후 레코드를 딕셔너리로 반환한다.

```python
records = []

with path.open("r", encoding="utf-8", newline="") as file:
    reader = csv.DictReader(file)
    for row in reader:
        records.append(row)

print(records[0]["name"])  # Alice
print(records[0]["age"])   # '20'
```

CSV에서 읽은 모든 필드는 기본적으로 문자열이다. 숫자·날짜·불리언처럼 사용할 필드는 입력 규칙에 따라 명시적으로 변환한다.

## 4. CSV 입력 계약 정하기

CSV는 프로그램마다 구분자와 따옴표 규칙이 다를 수 있다. 입력을 받기 전에 다음 계약을 정한다.

| 항목 | 이 절의 예제 규칙 |
| --- | --- |
| 인코딩 | UTF-8 |
| 구분자 | 쉼표 `,` |
| 따옴표 | 큰따옴표 `"` |
| 헤더 | `name`, `age`, `city` 필수 |
| 자료형 | `age`는 0~130 정수 |
| 빈 값 | 모든 필드에서 허용하지 않음 |

탭 구분 파일이나 세미콜론 구분 파일을 처리해야 한다면 `delimiter`를 명시한다. `csv.Sniffer`의 추론 결과만 신뢰해 스키마 검증을 생략하지 않는다.

```python
reader = csv.reader(
    ["name;age;city", "Alice;20;Seoul"],
    delimiter=";",
)

print(list(reader))
```

## 5. 헤더·행 구조·자료형 검증

`DictReader`는 헤더보다 값이 많은 행의 남는 값을 `None` 키에 리스트로 모으고, 값이 부족한 행의 누락 필드에 `None`을 넣는다. 빈 셀은 `None`이 아니라 빈 문자열 `""`이므로 따로 검사한다.

```python
REQUIRED_FIELDS = {"name", "age", "city"}
ALLOWED_FIELDS = {"name", "age", "city"}


def validate_headers(fieldnames):
    if fieldnames is None:
        raise ValueError("CSV 헤더가 없습니다")
    if any(name is None or not name.strip() for name in fieldnames):
        raise ValueError("비어 있는 CSV 헤더가 있습니다")
    if len(fieldnames) != len(set(fieldnames)):
        raise ValueError("중복 CSV 헤더가 있습니다")

    names = set(fieldnames)
    missing = REQUIRED_FIELDS - names
    unknown = names - ALLOWED_FIELDS

    if missing:
        raise ValueError(f"필수 헤더 누락: {sorted(missing)}")
    if unknown:
        raise ValueError(f"알 수 없는 헤더: {sorted(unknown)}")


def parse_person(row):
    if None in row:
        raise ValueError("헤더보다 값이 많은 레코드입니다")
    if any(value is None for value in row.values()):
        raise ValueError("필드가 누락된 레코드입니다")

    name = row["name"].strip()
    age_text = row["age"].strip()
    city = row["city"].strip()

    if not name or not age_text or not city:
        raise ValueError("빈 필드가 있습니다")

    age = int(age_text)
    if not 0 <= age <= 130:
        raise ValueError("나이는 0부터 130 사이여야 합니다")

    return {
        "name": name,
        "age": age,
        "city": city,
    }
```

구조 검증을 자료형 변환보다 먼저 수행한다. `parse_person()`은 원본 딕셔너리를 직접 수정하지 않고 검증된 새 딕셔너리를 반환한다.

## 6. 오류 위치와 원인 보존하기

`strict=True`는 잘못 닫힌 따옴표 같은 일부 CSV 문법 오류를 더 엄격하게 검사하지만, 헤더와 자료형까지 검증하지는 않는다.

```python
def load_people(path):
    valid_records = []
    errors = []

    with path.open(
        "r",
        encoding="utf-8",
        newline="",
    ) as file:
        reader = csv.DictReader(
            file,
            delimiter=",",
            quotechar='"',
            strict=True,
        )

        try:
            validate_headers(reader.fieldnames)

            for record_number, row in enumerate(reader, start=1):
                try:
                    record = parse_person(row)
                except (KeyError, TypeError, ValueError) as exc:
                    errors.append({
                        "record": record_number,
                        "line": reader.line_num,
                        "error": str(exc),
                    })
                    continue

                valid_records.append(record)
        except csv.Error as exc:
            raise ValueError(
                f"CSV 문법 오류(물리 행 {reader.line_num}): {exc}"
            ) from exc

    return valid_records, errors


valid_records, errors = load_people(path)
print(valid_records)
print(errors)
```

`reader.line_num`은 현재 레코드까지 읽은 **물리적 줄 수**다. 따옴표로 감싼 필드 안에 줄바꿈이 있으면 레코드 번호와 물리 행 번호가 달라질 수 있으므로 둘을 구분해 기록한다.

원본 행 전체를 오류 기록에 남기면 재처리에 도움이 되지만 계정·토큰·개인정보가 함께 기록될 수 있다. 운영 환경에서는 필요한 필드만 남기거나 민감값을 마스킹하고, 원본 격리 파일의 접근 권한과 보존 기간을 정한다.

## 7. DictWriter로 쓰기

`DictWriter`는 출력 열과 순서를 `fieldnames`로 고정한다.

```python
OUTPUT_FIELDS = ["name", "age", "city"]

with (lab_dir / "people_valid.csv").open(
    "w",
    encoding="utf-8",
    newline="",
) as file:
    writer = csv.DictWriter(
        file,
        fieldnames=OUTPUT_FIELDS,
        extrasaction="raise",
    )
    writer.writeheader()
    writer.writerows(valid_records)
```

`extrasaction="raise"`는 출력 스키마에 없는 키가 있을 때 조용히 버리지 않고 오류를 발생시킨다. 반대로 키가 부족하면 빈 셀로 기록되므로 쓰기 전에도 필수 필드 검증이 필요하다.

CSV에는 JSON의 `null`처럼 공통으로 합의된 결측값 표현이 없다. `csv.writer`는 `None`을 빈 문자열로 기록하므로 `None`과 원래 빈 문자열을 다시 구분해야 한다면 입력·출력 계약에서 별도 표기 규칙을 정한다.

## 8. UTF-8 BOM과 스프레드시트 호환

스프레드시트 프로그램과 교환하면서 UTF-8 BOM이 필요하다는 입력·출력 계약이 있다면 `utf-8-sig`를 사용한다.

```python
with (lab_dir / "people_excel.csv").open(
    "w",
    encoding="utf-8-sig",
    newline="",
) as file:
    writer = csv.DictWriter(file, fieldnames=OUTPUT_FIELDS)
    writer.writeheader()
    writer.writerows(valid_records)
```

`utf-8-sig`가 모든 프로그램의 CSV 호환 문제를 해결하는 것은 아니다. 구분자, 날짜·숫자 표기와 문자 인코딩을 교환 대상과 함께 확인한다. BOM을 허용하는 입력 파일은 `encoding="utf-8-sig"`로 읽으면 첫 헤더 앞의 BOM을 제거할 수 있다.

## 9. 스프레드시트 수식 해석 위험

CSV 자체는 코드를 실행하지 않는다. 그러나 일부 스프레드시트는 `=`, `+`, `-`, `@` 등으로 시작하는 셀을 수식으로 해석한다. CSV 따옴표는 구분자 표현 규칙일 뿐 수식 해석을 막는 보안 장치가 아니다.

외부 입력을 사람이 스프레드시트에서 열 예정이라면 열별 정책을 정한다.

- 이름·메모처럼 수식이 필요 없는 텍스트 열은 허용 형식을 검증한다.
- 수식 접두 문자로 시작하는 텍스트는 거부하거나 별도 검토 대상으로 격리한다.
- 숫자 열의 음수와 텍스트 열의 `-` 시작 값을 같은 규칙으로 처리하지 않는다.
- 특정 문자 앞에 작은따옴표를 붙이는 방식은 원본을 바꾸고 제품별 동작이 다르므로 검증 없이 공통 해결책으로 사용하지 않는다.
- 파일을 여는 스프레드시트의 외부 연결·매크로·수식 실행 정책도 함께 제한한다.

```python
FORMULA_PREFIXES = ("=", "+", "-", "@")


def validate_spreadsheet_text(value):
    if value.lstrip().startswith(FORMULA_PREFIXES):
        raise ValueError(
            "스프레드시트 수식으로 해석될 수 있는 텍스트입니다"
        )
    return value


safe_name = validate_spreadsheet_text("Alice")
print(safe_name)
```

이 함수는 수식이 허용되지 않는 **텍스트 필드**에만 적용한다. 입력을 거부·격리할지, 별도 안전 형식으로 내보낼지는 서비스 요구사항과 대상 스프레드시트에 맞게 결정한다.

## 흔한 실수

- CSV를 `split(",")`로 직접 분리한다.
- 숫자 필드를 문자열 상태로 계산한다.
- 헤더 누락·중복·빈 이름·알 수 없는 열을 확인하지 않는다.
- 부족한 열의 `None`과 빈 셀의 `""`을 같은 것으로 생각한다.
- `strict=True`가 업무 스키마까지 검증한다고 생각한다.
- 레코드 번호와 따옴표 안 줄바꿈을 포함한 물리 행 번호를 혼동한다.
- CSV 파일을 열 때 `newline=""`을 생략한다.
- 오류 로그에 민감한 원본 행을 그대로 남긴다.
- CSV 따옴표가 스프레드시트의 수식 해석을 막는다고 생각한다.

### 🧪 종합 실습: 상품 CSV 검증기

다음 사례를 포함한 상품명·가격·수량 CSV를 준비한다.

- 정상 상품
- 쉼표가 포함된 상품명
- 빈 상품명
- 숫자가 아닌 가격
- 음수 수량
- 누락·초과 필드
- `=2+3`처럼 수식으로 해석될 수 있는 상품명

프로그램은 다음 작업을 수행해야 한다.

1. 인코딩·구분자·헤더 계약을 명시한다.
2. 헤더, 행 구조, 빈 값, 가격·수량의 정수 변환과 범위를 검증한다.
3. 정상 레코드에는 `total = price * quantity`를 추가한다.
4. 오류에는 레코드 번호, 물리 행 번호와 원인을 남기되 민감값은 기록하지 않는다.
5. 정상 레코드를 새 CSV로 저장하고 다시 읽어 헤더와 건수를 확인한다.
6. 수식 위험 입력은 정상 출력과 분리한다.

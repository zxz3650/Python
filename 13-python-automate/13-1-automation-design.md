# 13-1. DFIR 자동화 과제와 분석 범위

> **핵심 질문** · 자동 분석이 끝났다는 것과 사건을 판단했다는 것은 어떻게 다를까요?

초기 분석에서 반복되는 작업은 수집 목록 확인, 파서 실행, 결과 정리, 시간순 정렬, 조건에 맞는 행 추출입니다. 정상적인 관리 작업인지 실제 침해인지를 판단하고 조치 순서를 정하려면, 당시의 작업 이력과 추가 자료를 확인해야 합니다. 자동화의 목표는 이 판단에 필요한 자료를 빠짐없이 모으는 것입니다.

## 1. 분석 계획서

| 항목 | 이번 실습에서 정할 내용 |
| --- | --- |
| 사건 | 합성 사건 `SYNTHETIC-CASE-001` |
| 호스트 | `HOST-A`, `HOST-B`; 자료별 호스트를 manifest에 명시 |
| 입력 | 완료된 CSV 내보내기 결과, 파서 이름·버전, 열 매핑 |
| 원본 보관 | 수집 원본과 CSV는 읽기만 수행 |
| 시간 | UTC로 정규화하되 원래 시각과 시각 의미를 보존 |
| 자동 작업 | 필드 검증·시간 정렬·조건 일치·같은 경로가 기록된 자료 조회 |
| 사람의 판단 | 정상 배포·관리 접속 여부, 침해 여부, 추가 수집 범위 |
| 출력 | 실행별 새 폴더의 JSONL·JSON·HTML·처리 완료 표시 파일 |
| 실패 | 잘못된 manifest·경로·크기 제한이면 중단; 행 오류·누락은 부분 처리로 보고 |

## 2. 확인할 내용에 맞는 자료 찾기

| 질문 | 필요한 자료 | 이 자료만으로 부족한 점 |
| --- | --- | --- |
| 로그온 실패가 짧은 시간에 반복됐나? | Security 이벤트, 계정·출발 IP·시각 | 오입력·자동화 계정 오류 가능 |
| 어떤 프로세스 생성이 기록됐나? | Sysmon 프로세스 생성, 실행 경로 | 경로만으로 악성 판단 불가 |
| 자동 실행 등록이 존재하나? | Run/RunOnce 값, 서비스·예약 작업 자료 | 등록이 실제 실행을 뜻하지 않음 |
| 동일 경로가 다른 아티팩트에도 있나? | 이벤트·Prefetch·MFT·레지스트리 | 같은 파일명·경로만으로 동일 파일 내용 보장 불가 |
| 여러 호스트의 접속이 시간상 가까운가? | 호스트별 로그온, 계정·IP·UTC | NAT·시계 오차·정상 관리 작업 고려 필요 |

## 3. 무엇을 점수로 표시할까요?

예제는 **검토 우선순위**를 규칙별 20·30·40으로 표시합니다. 교육용 정렬 값이며 CVSS, 침해 확률, 실제 위험도를 평가하는 점수이 아닙니다. 여러 엔진이 같은 이벤트를 탐지했다고 점수를 계속 더하지 않습니다.

MITRE ATT&CK는 공격자가 사용하는 기법을 정리한 분류 체계입니다. Run 키에 등록된 항목을 검토할 때는 관련 기법인 `T1547.001`을 참고할 수 있습니다. 다만 정상 프로그램도 Run 키를 사용하므로 등록 내용과 실행 기록을 함께 확인해야 합니다. 원래 규칙 ID·버전·근거를 함께 보존합니다.

## 4. 재현 가능성

```text
내용이 같은 입력 파일 + 같은 manifest + 같은 코드·규칙 버전
→ 같은 정규화 레코드 식별자와 같은 조건 일치 결과
```

호스트 이름, 파서 버전, 열 매핑을 추측하지 않습니다. 사람이 manifest를 작성하고 실제 샘플 행과 대조합니다. 수집·분석 중 입력이 바뀌지 않는 오프라인 폴더를 전제로 합니다.

## 실습과 완료 기준

1. 자동 분석으로 답할 수 있는 질문 두 개와 추가 조사가 필요한 질문 두 개를 적습니다.
2. 누락된 자료를 0건이라고 표시했을 때 생기는 오해를 설명합니다.
3. 같은 자료를 다른 규칙 버전으로 분석할 때 무엇을 기록할지 정합니다.

- [ ] 분석 계획서에 입력 자료, 적용할 규칙, 출력 파일과 오류 처리 방법을 적었습니다.
- [ ] 우선순위와 침해 판정을 구분합니다.
- [ ] 실제 증거 대신 합성 자료로 먼저 검증합니다.

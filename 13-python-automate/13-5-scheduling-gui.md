# 13-5. 완료 감지·워커·재실행 관리

> **핵심 질문** · 폴더에 CSV가 보이기 시작하면 즉시 분석해도 될까요?

파서가 CSV를 쓰는 중일 수 있고, 한 호스트의 여러 결과 중 일부만 도착했을 수도 있습니다. 파일 생성 알림은 완료 신호가 아닙니다. 자동화에서는 **자료를 만드는 생산자와 분석하는 워커 사이의 완료 계약**이 필요합니다.

## 1. 기본 실행과 워커 확장을 구분합니다

제공 `pipeline.py`는 완료된 입력 manifest를 받아 한 번 분석하는 프로그램입니다. 폴더를 계속 감시하거나 KAPE를 자동 실행하는 워커는 포함하지 않습니다. 이 절에서는 기본 함수를 예약·큐 기반 작업으로 연결하는 설계를 학습합니다.

## 2. 완료 manifest를 마지막에 게시합니다

```mermaid
flowchart LR
    A["파서가 작업 폴더에 출력"] --> B["프로세스 종료 확인"]
    B --> C["필수 파일·헤더·해시 검증"]
    C --> D["ready manifest 마지막 게시"]
    D --> E["워커가 작업 점유"]
    E --> F["정규화·분석·보고"]
    F --> G["완료/부분 처리 마커"]
```

생산자는 출력 파일을 닫고 필수 결과를 확인한 뒤 완료 manifest를 게시합니다. 같은 파일시스템에서는 임시 manifest를 완성한 후 이름을 바꾸는 방식을 사용할 수 있습니다. 몇 초 동안 크기가 같다는 관찰만으로 생산자의 완료를 확정하지 않습니다.

## 3. 상태 전이

| 상태 | 전환 조건 | 보존할 내용 |
| --- | --- | --- |
| `waiting` | 완료 입력을 기다림 | 사건·호스트·기대 자료 |
| `ready` | 생산자가 완료 manifest 게시 | 파일 해시·파서·옵션 |
| `running` | 워커가 원자적으로 작업 점유 | 작업 ID·워커·시작 시각 |
| `complete` | 모든 선언 자료를 정상 처리 | 결과 해시·버전·완료 마커 |
| `partial` | 일부 자료 누락·행 오류·파싱 실패 | 정상 결과와 누락·오류 목록 |
| `failed` | 작업 계약·자원·저장 오류 | 실패 단계·부분 출력 위치 |

기본 코드의 `complete.json`은 **결과 파일 쓰기가 끝났다는 표시**입니다. 그 안의 `processing_status`가 `partial`일 수도 있습니다. 마커 파일 이름만 보고 자료가 모두 정상 처리되었다고 판단하지 않습니다.

## 4. 종료 코드를 해석합니다

| 코드 | 기본 파이프라인의 의미 |
| --- | --- |
| 0 | 보고서 저장 완료, 선언한 입력의 누락·처리 오류 없음 |
| 1 | manifest·경로·자원 한도·입출력 오류 등으로 실행 실패 |
| 2 | 보고서 저장 완료, 누락·파싱 실패·행 오류가 있어 부분 처리 |

검토 항목의 수는 실행 성공 여부와 별개입니다. 시각 없는 유효 레코드는 `undated`로 표시하며, 시간 상관 규칙의 대상에서는 제외합니다.

## 5. 중복과 재실행

작업 키에는 사건 ID·입력 manifest 해시·코드 버전·규칙 버전을 포함합니다. 워커 여러 개가 같은 작업을 동시에 잡지 않도록 큐나 잠금을 설계하고, 죽은 워커의 점유를 해제할 정책도 정합니다.

기본 코드는 기존 출력 폴더를 거부합니다. 재분석은 `kape-report-02`처럼 새 폴더에 수행합니다. 결과 쓰기 도중 중단되면 폴더가 남을 수 있지만 `complete.json`이 없으므로 완료 결과로 사용하지 않습니다. 해당 폴더를 자동 삭제하지 않고 실패 이력을 확인합니다.

## 6. 처리량과 정보 보존

기본 구현은 입력 파일당 25 MiB, 사건당 읽은 CSV 100,000행으로 제한합니다. 전부 메모리에 보관하는 학습용 구조이므로 대규모 사건에서는 SQLite·Parquet·스트리밍 저장으로 확장합니다. 엔진 수만큼 워커를 무제한 늘리면 메모리·디스크가 먼저 고갈될 수 있습니다.

알림에는 사건 ID·처리 상태·검토 항목 수·오류 수·보고서 위치를 우선 포함합니다. 계정·명령행·원문 증거를 메신저나 외부 AI 서비스에 자동 전송하지 않습니다.

## 실습과 완료 기준

1. 동일 출력 경로로 두 번 실행해 덮어쓰기 거부를 확인합니다.
2. `partial` 결과를 정상 완료와 별도 표시하는 워커 의사코드를 작성합니다.
3. 파일은 있지만 완료 마커가 없는 결과를 어떻게 다룰지 정합니다.

- [ ] 파일 생성과 생산 완료를 구분합니다.
- [ ] 재시도·중복 점유·부분 출력을 처리하는 정책이 있습니다.
- [ ] 종료 코드와 검토 항목 수를 구분합니다.

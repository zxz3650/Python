# 13-4. 공통 스키마·시간 정규화·보고서

> **핵심 질문** · 여러 CSV에 모두 Time 열이 있다면 그대로 합쳐도 될까요?

이벤트 생성 시각, Prefetch의 마지막 실행 시각, 레지스트리 키 LastWrite, MFT의 파일 생성 시각은 서로 다른 사실을 나타냅니다. 하나의 타임라인에 표시하더라도 원래 의미를 보존해야 합니다.

## 1. 여러 CSV를 같은 필드 구조로 정리하기

| 필드 | 의미 |
| --- | --- |
| `case_id`, `host` | 사건과 수집 대상 호스트 |
| `artifact` | `evtx`, `prefetch`, `mft`, `registry` 등 자료 종류 |
| `timestamp_original` | CSV에서 읽은 시각 문자열 |
| `timestamp_utc` | UTC 변환 결과; 시각이 없으면 `null` |
| `timestamp_kind` | 이벤트 생성·파일 생성·키 갱신 등 시각의 의미 |
| `event_id`, `channel`, `provider`, `record_id` | EVTX 해석과 원본 이벤트 구분 |
| `user`, `src_ip`, `path` | 조건 검사·관련 근거 조회에 사용할 값 |
| `source_id`, `source_file`, `source_sha256`, `source_record` | 원본 CSV 파일과 해당 레코드를 찾는 정보 |
| `parser`, `parser_version`, `uid` | 파서 정보와 레코드 식별자(UID) |

필드 이름과 자료형을 정한 구조를 **스키마**라고 합니다. 아래 실습에서는 위 표의 구조를 공통으로 사용하며, 도구마다 다른 CSV 열 이름을 이 구조에 맞춥니다. 기본 코드는 CSV 한 행에서 대표 시각 하나를 읽습니다. 한 행에 여러 실행 시각이 있다면, 이를 별도 기록으로 나누는 코드를 확장 실습에서 작성합니다. 원본 CSV는 보존합니다.

## 2. 시간대가 없으면 추측하지 않습니다

```text
2026-09-01T09:06:00+09:00 → 2026-09-01T00:06:00Z
2026-09-01T00:06:00Z      → 그대로 UTC
2026-09-01 09:06:00       → UTC와의 시차 설정이 없으면 입력 오류
빈 시각                    → null로 보존, 시간 간격을 비교하는 규칙에서는 제외
```

파서 문서와 수집 설정으로 로컬 시각임을 확인했을 때만 source의 `utc_offset`을 `+09:00`처럼 명시합니다. 분석 PC의 시간대를 자동 적용하지 않습니다. 고정 오프셋은 일광절약시간 전환이나 호스트 시계 오차를 해결하지 않으므로 해당 사건에는 별도 시간대·시계 보정 근거가 필요합니다.

기본 구현은 ISO 날짜·시각과 마이크로초까지 지원합니다. Windows의 더 높은 정밀도나 다른 날짜 형식은 임의로 자릿수를 줄이지 않고 입력 오류로 기록합니다. 실제 자료를 처리할 때는 원래 시각 문자열과 소수점 자릿수를 보존할 수 있도록 변환 코드를 보완해야 합니다.

## 3. 아티팩트마다 별도 어댑터가 필요한 이유

Prefetch의 여러 실행 시각을 여러 이벤트로 펼치거나, MFT의 부모 경로와 파일명을 결합하거나, EVTX 파서의 복합 Payload 필드에서 계정·IP를 꺼내는 작업은 단순 열 이름 변경만으로 끝나지 않습니다. 이처럼 파서의 출력에서 필요한 값을 꺼내 공통 형식으로 바꾸는 코드를 **어댑터**라고 합니다. 파서 버전과 출력 설정에 맞게 작성하고, 변환 결과를 원본 샘플과 대조합니다.

다음 단계로 확장할 때에도 시각 없는 Shimcache 항목을 수집 시각으로 대체해 “실행됨”이라고 표시하지 않습니다. Amcache의 존재만으로 실행을 확정하지 않습니다.

## 4. pandas로 집계하기 전에 자료형과 빈 값 확인하기

05장에서 학습한 pandas로 결과를 집계할 수 있습니다. 아래 코드는 프로젝트 실행 후 저장소 루트에서 수행합니다. pandas는 기본 파이프라인의 필수 의존성은 아닙니다.

```python
import pandas as pd

frame = pd.read_json("outputs/kape-report-01/normalized.jsonl", lines=True)
counts = frame.groupby(["host", "artifact"], dropna=False).size().reset_index(name="records")
print(counts)
```

`read_csv()`로 원본을 읽을 때 계정명·기록 ID·이벤트 ID를 숫자로 자동 변환하거나 빈 값을 임의로 채우지 않습니다. 예를 들어 문자열로 보관해야 하는 ID는 `dtype`으로 자료형을 지정하고, 빈 값은 제외할지 그대로 남길지 정합니다. 집계 후에는 원본 행 수와 오류 건수를 비교해 빠진 자료가 없는지 확인합니다.

## 5. 보고서에 담을 네 가지 항목

| 항목 | 확인할 내용 |
| --- | --- |
| 처리 범위 | 무엇을 받았고 무엇이 누락·실패했는가? |
| 검토 항목 | 어떤 조건이 일치했고 근거 UID는 무엇인가? |
| 통합 타임라인 | 호스트·UTC·아티팩트·시각 의미·출처가 무엇인가? |
| 입력 오류 | 어떤 자료의 어느 레코드를 다시 확인해야 하는가? |

기본 산출물은 외부 연결이 없는 HTML과 전체 JSON/JSONL입니다. HTML에는 타임라인 최대 1,000건을 표시하고 전체 결과 위치를 안내합니다. 시각 없는 레코드는 시간 있는 레코드 뒤에 놓습니다. 표시 순서는 인과관계의 증명이 아닙니다.

XLSX 확장 시에는 시간대를 텍스트 열로 보존하고 시각 변환 기준을 적습니다. Excel의 날짜 셀만으로 시간대가 유지된다고 가정하지 않습니다. 외부 문자열을 수식으로 해석하지 않도록 텍스트 형식의 셀로 저장하고, 원본 CSV는 그대로 보관합니다.
